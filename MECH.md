# MECH.md — спецификация ядра игры (game8885)

Документ описывает **точную** семантику ядра симуляции «Игры 8885» в
текущей реализации. Это источник истины для проверки кода: каждый пункт
сопоставим с конкретной функцией в `src/`. Нумерация пунктов используется
в актах верификации.

Обозначения: `N(s)` — численность вида `s` (число живых особей),
`B(s)` / `C(s)` — счётчики `blocked` / `cross` вида `s`,
`F` — число свободных слотов, `S` — размер поля.

---

## 1. Объекты и типы

1.1. **Вид** — `Pure b` (исходный) или `Mix b b` (гибрид двух исходных);
компоненты гибрида нормализованы (упорядочены) конструктором `mix`.
(`src/Species.hs: data Species`, `mix`)

1.2. **Жизнь особи** — `Life { age :: Int, death :: Rational }`:
`age` — число прожитых ходов, `death` — текущая вероятность умереть
в конце хода. (`src/Species.hs: data Life`)

1.3. **Поле** — `Space`:
`freeSpace :: Int` (свободные слоты),
`population :: Map (Species b) [Life]` (особи по видам, **индивидуально**),
`blocked :: Map (Species b) Int` (заблокированные в этом ходу),
`cross :: Map (Species b) Int` (только что размножавшиеся с чужим цветом),
`histogram :: Map (Species b) (Map Int Int)` (возраст смерти → число особей).
(`src/Species.hs: data Space`)

1.4. **Окружение** — `Env`: `spaceSize` (Поле), `initial` (Начало),
`win` (Победа), `rape` (Изнасилование), `maxSteps` (Максимум шагов),
`killReward` (Награда за убийство), `reproPenalty` (Штраф за размножение).
(`src/Species.hs: data Env`)

1.5. **Правила** — `Tables`: генератор случайности, базовые виды,
все виды, окружение, поле, резолвер имён, карты правил (действия,
партнёры, убийство, симпатии, рождение) и параметры конечной жизни:
`lifeStart` (Смертность), `lifeScale` (Долголетие), `killSuccess`
(Успех убийства), `offspring` (Потомство). (`src/Pattern.hs: data Tables`)

## 2. Ход игры (полный цикл)

2.1. `stepTurn` делает **один ход** и возвращает результат завершения
игры (Nothing — игра продолжается). (`src/Sim.hs: stepTurn`)

2.2. В начале хода снимается снимок `remaining`: число действий,
оставшихся у каждого вида (равно численности на начало хода).

2.3. Цикл действий:
  a) сначала проверяются условия завершения (`checkEnd`); если игра
     завершилась — `finishTurn (Just r)` (см. 2.5);
  b) из видов с `remaining > 0` и `N(s) > 0` случайно выбирается вид
     **с весом, равным remaining** (`sampleWeighted`);
  c) действует случайная особь этого вида (`actSpecies`, см. 3);
  d) `remaining` выбранного вида уменьшается на 1; цикл повторяется,
     пока есть подходящие виды.

2.4. Когда подходящих видов не осталось — `finishTurn Nothing`.

2.5. `finishTurn`:
  a) если игра уже завершилась — `blocked`/`cross` очищаются, старение
     **не** выполняется;
  b) иначе — фаза конечной жизни `ageAndDie` (см. 7), затем
     `blocked`/`cross` очищаются и условия завершения проверяются
     **снова** (вымирание возможно от старости).

2.6. Каждый живой чибик действует ровно один раз за ход (в случайном
порядке); заблокированные чибики действуют, но не могут быть выбраны
партнёром.

## 3. Действие особи

3.1. `actSpecies s` выбирает случайную особь вида `s` (индекс в списке)
и выполняет: `decideAction` → `tryAction`; если действие невозможно —
пробуется второе; если убийство промахнулось — ход потрачен, второе
действие не пробуется. (`src/Sim.hs: actSpecies`)

3.2. `decideAction s` по правилу вида:
  * `N%` — убийство с вероятностью `N`, иначе размножение;
  * `~смешанные~` — убийство, только если есть чужие «смешанные»
    (виды `t ≠ s` с `C(t) > 0`);
  * `N% ~смешанные~` — то же, но с вероятностью `N`.
  (`src/Sim.hs: decideAction`, `hasCrossTarget`; тип `ActionRule` в
  `src/Pattern.hs`)

## 4. Убийство

4.1. `chooseVictim s` по правилу `Убийство:` вида: жертвы — виды,
подходящие хотя бы под один токен цели, не входящие в исключения,
с `N(s') − [s' == s] > 0`; вид-жертва выбирается **взвешенно по
численности особей**. Нет жертв → действие невозможно.
(`src/Sim.hs: chooseVictim`)

4.2. Успех убийства: с вероятностью `killSuccess(s)` (Успех убийства)
попытка удаётся; при неудаче жертва не умирает, ход потрачен
(`ARMissed`), награда не начисляется. (`src/Sim.hs: tryAction Kill`)

4.3. При успехе: случайная особь вида-жертвы погибает (`killOne`):
удаляется из `population`, `F += 1`, счётчики `B(v)`/`C(v)` ужимаются
до новой численности (`min`), возраст смерти записывается в гистограмму
вида. (`src/Sim.hs: killOne`, `killAt`, `recordDeath`)

4.4. Награда: `death` убийцы уменьшается:
`death := max(0, death − R)`, `R = Env.killReward`.
(`src/Sim.hs: applyKillReward`)

## 5. Размножение

5.1. Требуется `F > 0`, иначе действие невозможно.
(`src/Sim.hs: tryAction Fuck`)

5.2. `choosePartner s` по правилу `Партнёры:` вида:
  * число доступных партнёров вида `s'`:
    `max(0, N(s') − B(s')) − [s' == s ∧ актор не заблокирован]`;
  * **предпочтительный** пул: виды, подходящие под токены
    предпочтений, с числом партнёров > 0; выбор — **равномерно среди
    видов** пула;
  * если предпочтительный пул пуст и условие (если задано) истинно —
    **запасной** пул (те же правила); иначе партнёра нет.
  (`src/Sim.hs: choosePartner`)

5.3. `sympathyProb a p` — согласие принимающей стороны `p` к
инициатору `a`: свои виды всегда 100% (правило 3); иначе первое
подходящее правило `Симпатии:` (правила отсортированы по конкретности
паттерна инициатора, убывание; внутри — первая подходящая клауза с
учётом условий); если ни одно не подошло — 50/50.
(`src/Sim.hs: sympathyProb`)

5.4. Согласие разыгрывается с этой вероятностью. При отказе:
с вероятностью `Env.rape` (Изнасилование) размножение всё равно
происходит; иначе **партнёр убивает инициатора** (именно эту особь,
`killAt a i` — гибель и слот освобождаются, возраст в гистограмму).
(`src/Sim.hs: fuckFlow`)

5.5. `doRepro a p`: число потомков `n` разыгрывается из распределения
`offspring(a)` (Потомство). Если `n = 0` — ничего не происходит:
потомков нет, родители не блокируются, «смешанные» не помечаются,
штраф не применяется. (`src/Sim.hs: doRepro`)

5.6. При `n > 0`: дети создаются по одному, пока `F > 0` (создаётся
не более `min(n, F)` детей). Каждый ребёнок — `creationResult` (см. 6),
начинает с `age = 0` и `death = Смертность(child)`; `F -= 1`.
(`src/Sim.hs: createChild`)

5.7. После рождения детей: `B(a) += 1`, `B(p) += 1` (для `a == p`
суммарно +2), каждый ребёнок `B(child) += 1` (правило 2 — родители и
дети заблокированы до конца хода). Если `a ≠ p`, то `C(a) += 1` и
`C(p) += 1` («смешанные» — цели белых). (`src/Sim.hs: doRepro`)

5.8. Штраф: `death` инициатора увеличивается:
`death := min(1, death + C)`, `C = Env.reproPenalty`.
(`src/Sim.hs: doRepro`)

## 6. Рождение (вид потомка)

6.1. `creationResult a p`: если `a == p` — потомок вида `a`
(правило 3). (`src/Sim.hs: creationResult`)

6.2. Иначе применяется первое подходящее правило `Рождение:`
(правила отсортированы по сумме конкретностей паттернов инициатора и
партнёра, убывание); среди его клауз-результатов, разрешимых в
существующий вид, выбирается один **взвешенно по вероятностям**.
Если ни одно правило не подошло — потомок — цвет одного из родителей
(50/50). Результат может быть видом, переменной или гибридом `(X, Y)`.
(`src/Sim.hs: creationResult`, `resolveResult`)

## 7. Конечная жизнь (старение и смерть)

7.1. В конце хода (`ageAndDie`) для каждого вида, для каждой особи:
  a) особь умирает с вероятностью `death`; при смерти: возраст
     записывается в гистограмму вида (`histogram(s)[age] += 1`),
     особь удаляется, `F += 1`;
  b) выжившая особь: `age += 1`, `death := min(1, death + 1/L)`,
     где `L = lifeScale(s)` (Долголетие).
(`src/Sim.hs: ageAndDie`)

7.2. **Закон старения**: `death(t) = min(1, p0 + t/L)`, где
`p0 = lifeStart(s)` (Смертность), `t` — возраст. Ожидаемая
продолжительность жизни свободного чибика ≈ `sqrt(π·L/2)`
(анализ и симуляции — `SIMS.md`).

7.3. События в течение хода меняют `death` немедленно (влияют на
ближайшую проверку в конце хода): успешное убийство — `−R`
(п. 4.4), успешное размножение с `n > 0` — `+C` (п. 5.8).

## 8. Гистограммы продолжительности жизни

8.1. `histogram(s)` накапливает возраст смерти каждой особи вида `s`
(все причины смерти: убийство, гибель от отказа, старость).
(`src/Sim.hs: recordDeath`)

8.2. Сервер отправляет гистограммы в сообщениях `init` и `state` как
`lifespans`: для каждого вида массив, индексированный возрастом
(индекс = возраст, значение = число умерших). Обновляется **каждый
ход**. (`src/Ctx.hs: lifespanArrays`, `src/Cmd.hs`)

8.3. UI отображает гистограмму по видам и обновляет её при каждом
`state`. (`public/js/main.js: updateHist`)

## 9. Условия завершения

9.1. `checkEnd` (в порядке проверки): (`src/Sim.hs: checkEnd`)
  a) `F == 0` → «Поле полностью заполнено»;
  b) суммарная численность `< 5` → «Вымирание: на поле осталось менее
     5 чибиков»;
  c) первый вид (в порядке обхода карты) с `N(s) ≥ Env.win` →
     «Победа вида: <имя>».

9.2. Дополнительно (в `Ctx.stepGame`, не в ядре): при `Env.maxSteps > 0`
и достижении лимита шагов игра завершается «Достигнут лимит шагов».

## 10. Начальное поле

10.1. `initialSpace`: каждый исходный вид получает `Env.initial`
особей `Life 0 (Смертность(вида))`; `F = S − число_видов · initial`;
гистограмма пуста, `blocked`/`cross` — нули.
(`src/Sim.hs: initialSpace`)

## 11. Инварианты

11.1. `F + Σ_s N(s) = S` всегда. (`src/Test.hs: checkInvariants`)
11.2. `B(s) ≤ N(s)` и `C(s) ≤ N(s)` для всех `s`.
11.3. Для каждой особи: `age ≥ 0`, `0 ≤ death ≤ 1`.

## 12. Действия доминирующего вида и условия

12.1. `~доминирующий~` — вид(ы) с максимальной `N(s)`; при равенстве —
случайный из максимумов. (`src/Sim.hs: dominantSpecies`)

12.2. Условия `[Вид < N]`, `[Вид <= N]`, `[Вид > N]`, `[Вид >= N]`
сравнивают текущую численность вида. (`src/Pattern.hs: evalCond`)

## 13. Язык правил (DSL)

13.1. Секции (порядок произвольный; обязательна только `Базовые виды:`):
`Базовые виды`, `Синонимы` (гибриды `A x B ~ Имя;`), `Параметры`,
`Цвета`, `Действия` (алиас `Склонность к убийству:`), `Смертность`,
`Долголетие`, `Успех убийства`, `Потомство`, `Партнёры`, `Убийство`,
`Симпатии`, `Рождение`. Записи заканчиваются `;`. Комментарии
`/* ... */` и `//`. (`src/Parser.hs`)

13.2. Параметры среды: `Поле` (int), `Начало` (int), `Победа` (int),
`Изнасилование` (%), `Максимум шагов` (int), `Награда за убийство` (%),
`Штраф за размножение` (%). Неизвестное имя параметра — ошибка.
(`src/Decl.hs: applyParam`)

13.3. `Смертность:` / `Успех убийства:` — `Вид: N%;` (`0..100`).
`Долголетие:` — `Вид: N;` (`N ≥ 1`).
`Потомство:` — `Вид: 0: N0% 1: N1% ...;`, **сумма обязана быть ровно
100%**; иначе ошибка валидации.
(`src/Decl.hs: compilePercentMap`, `compileScaleMap`, `compileOffspring`)

13.4. Токены паттернов: `*`, имя, переменная (ЗАГЛАВНЫЕ), `~я~`,
`~родители~`, `~чистый~`, `~гибрид~`, `~доминирующий~`, `~смешанные~`;
паттерн `(A, B)` — гибрид. (`src/Parser.hs: parseToken`, `parseP2`)

13.5. Правило `*` в секциях `Действия:`, `Партнёры:`, `Убийство:`,
`Смертность:`, `Долголетие:`, `Успех убийства:`, `Потомство:` задаёт
умолчание для видов без собственной записи. (`src/Decl.hs`)

13.6. Умолчания в коде при отсутствии записей: вероятность убийства 0%,
партнёр — `[*] -> []`, убийство невозможно, Смертность 1%,
Долголетие 60, Успех убийства 100%, Потомство — ровно 1 потомок.
(`src/Decl.hs: compile*`)

13.7. Проценты в `Симпатиях:`, `Рождении:`, `Смертности:`, `Успехе
убийства:` — абсолютные вероятности; в `Потомстве:` — распределение.

## 14. Протокол WebSocket

14.1. Клиент → сервер (`type`): `init`, `start`, `pause`, `restart`,
`step`, `update` (перечитать текущий файл правил и перезапустить),
`list`, `select {file}`; строковые события `"Init"`/`"Step"`.
(`src/Cmd.hs: ClientMsg`)

14.2. Сервер → клиент:
  * `hello {rules, default}` — при подключении;
  * `init {ruleSet, step, free, running, finished, result, species,
    steps, series, lifespans}` — полное состояние + история +
    гистограммы; после подключения и после restart/select/update;
  * `state {step, free, running, finished, result, population,
    lifespans}` — после каждого шага;
  * `error {message}`.
(`src/Cmd.hs: ServerMsg`)

## 15. Сервер и состояние

15.1. `GameState`: файл правил, `Tables`, номер шага, история
численностей (последние 20000), флаги running/finished, результат.
(`src/Ctx.hs: GameState`, `stepGame`)

15.2. Автошаги: тикер каждые 100 мс, пока running и не finished.
(`src/Ctx.hs: ticker`)

15.3. Постоянная конфигурация: файл `.game8885.conf` (JSON,
`{"lastRule": ...}`) хранит последний выбранный набор правил;
пишется только при успешном `select`, читается при старте сервера
(если файл существует и есть в списке правил — игра стартует с ним,
иначе с умолчания). (`src/Ctx.hs: readConfig`/`writeConfig`,
`src/Server.hs: launch`)

## 16. Зафиксированные решения (из SIMS.md)

16.1. Проверка смерти — в конце хода, с текущим `death` (после всех
событий хода); выжившие стареют и их `death` растёт.
16.2. Награда/штраф применяются к убийце/инициатору немедленно.
16.3. Промах убийства тратит ход (запасное действие не выполняется).
16.4. Размножение с нулём потомков не «успешно»: без штрафа,
блокировки и пометки «смешанных».
16.5. Вымирание от старости проверяется после фазы старения.
16.6. Жертва убийства — случайная особь; партнёр при отказе убивает
именно инициатора.
