# AGENT-INIT.md — краткое введение для нового агента

Быстрый старт для передачи проекта «Игра 8885» (zero-player симуляция
размножения/убийства с конечной жизнью). Подробности — в остальных
документах `docs/`.

## Что это

Поле из `Поле` слотов; `Базовые виды` чибиков; каждый ход каждый чибик
действует ровно один раз: **убить** или **размножиться**; у каждого чибика
есть возраст и вероятность смерти (растёт с возрастом по закону старения,
падает после убийства, растёт после размножения). Правила — в DSL
`rules/*.rule`; симуляция — Haskell; UI — WebSocket + ApexCharts.

## Ключевые файлы

- `../README.md` — обзор, DSL-секции, протокол, сборка.
- `docs/SPEC.md` — **точная семантика ядра** (источник истины; раздел 17 —
  тонкие места T1–T10, проверяются при верификации).
- `docs/LANGUAGE.md` — язык правил (DSL).
- `docs/SIMS.md` — математика конечной жизни (закон старения, подбор
  параметров) и симуляции.
- `docs/PLAN.md` — архитектура, решения, исправленные ошибки, статус.
- `docs/DYNAMICS.md` — мысли о том, как делать динамику интересной.
- `src/Sim.hs` — ядро (ход, действия, старение); `src/Species.hs` —
  типы; `src/Pattern.hs`/`Decl.hs`/`Parser.hs` — правила; `src/Ctx.hs`/
  `Cmd.hs`/`Server.hs`/`MainPage.hs` — сервер; `src/Test.hs` — тесты.

## Сборка / тесты / запуск

```sh
./build.sh            # сервер -> .build/game8885
./test.sh             # тесты
./run.sh              # сервер на http://127.0.0.1:8000
```

GHC/package-db — из снэпшота stack (см. начало `build.sh`); root-ФС может
быть read-only, поэтому stack напрямую не используется.

## Важнейшие особенности модели (не сломать!)

- **Индивидуальная модель**: `Space.population :: Map (Species b) [Life]`,
  каждая особь — `Life { age, death, acted }`. Актор — **индекс** в списке;
  награда/штраф применяются по индексу **до** любых удалений из списка
  (SPEC.md T1).
- **Каждая особь действует ровно один раз за ход** (флаг `acted`,
  сбрасывается в начале хода; `pickActor` выбирает только не действовавших).
- **Карты `blocked`/`cross` очищаются в конце каждого хода** — приращения
  обязаны идти через `M.insertWith (+)` (пересоздание записей), а не
  `M.adjust` (no-op для отсутствующих ключей — был критический баг);
  счётчики ужимаются до численности вида (инвариант `B ≤ N`, `C ≤ N`).
- Порядок фаз хода (SPEC.md 2.5, T3): `checkEnd` в начале каждой итерации;
  при завершении — **без** старения; иначе `ageAndDie` → очистка
  `blocked`/`cross` → повторный `checkEnd` (вымирание от старости).
- `n = 0` потомков — «неуспешное размножение»: без штрафа/блокировки/«смешанных».
- Весь рандом — через единую линзу `randGen`.
- Валидация DSL: сумма `Потомства` ровно 100%, `Долголетие ≥ 1`, имена
  видов в условиях и токенах обязаны резолвиться.

## Как верифицировать изменения

1. `./test.sh` — зелёный (включая регрессии по SPEC.md).
2. Динамика: `tools/balance.hs` (доли/исходы), `tools/osc.hs` (циклы
   бум-спад), `tools/trace.hs` (состав видов), `tools/lifespan.hs`
   (старение против теории).
3. Протокол: `tools/wscheck.hs` против запущенного сервера.
4. Сверка с `docs/SPEC.md` (пункты 1–17) — как в прошлых верификациях.

## Процесс

- Коммиты — частые и атомарные.
- При изменении семантики — синхронно обновлять `SPEC.md` и `LANGUAGE.md`.
- При изменении параметров правил — переснимать статистику в `SIMS.md`/
  `ChangeLog.md` и проверять динамику на `rules/triplet.rule`.
